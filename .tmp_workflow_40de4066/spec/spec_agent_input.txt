The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.
Design a synthesizable FPGA RTL top module named adaptive_aero_control_top. The module shall implement an active-aerodynamics control wrapper for an external NVIDIA DoMINO-based software/GPU surrogate. The RTL shall not implement the surrogate itself and shall not contain tensor math, ML layers, or large geometry arrays. The design shall include: (1) a 64-bit register-memory control/status window for firmware access; (2) a bounded valid/ready streaming interface no wider than 128 bits for request and response metadata; (3) a safety-and-fallback output path for actuator commands. The cfg_bus shall be a compact memory-mapped interface used to read and write configuration registers such as enable, mode select, stream_velocity_setpoint, min/max actuator clamp values, request_timeout_cycles, stale_threshold_cycles, sequence_id, geometry_ref_id, fault_ack, and status bits. The request stream shall package metadata only: request_id, sequence, geometry source identifier, geometry format tag, flow condition summary, velocity setpoint, and control flags. The response stream shall accept model result summary metadata only: response_id, sequence, status, health, digest of returned results, and a compact control recommendation scalar or vector summary. The top-level shall provide valid/ready handshake semantics, backpressure handling, and deterministic drop/reject behavior for late or malformed responses. A request shall be considered valid only when configuration is enabled, the external request fields are within allowed operating envelope, and the current state machine is not in fault latch. Sequence numbers shall monotonically increment and shall be matched on response; mismatched responses shall be discarded and flagged stale. Timeout logic shall count cycles since request launch and force safe fallback if no matching response is received before request_timeout_cycles. Stale-data logic shall compare current sequence and age against stale_threshold_cycles and assert stale_fault if the age exceeds threshold or if a response arrives after timeout. Safety_guard shall clamp the outgoing actuator command to configured bounds and assert clamp_active when saturation occurs. Safe fallback shall drive a conservative default actuator position defined in registers, override any surrogate-guided command, and remain active until fault_ack is observed after the fault condition clears. The design shall expose a status register block with sticky bits for timeout_fault, stale_fault, comm_fault, clamp_active, fallback_active, request_inflight, and last_sequence. The actuator command output shall be a compact scalar or packed vector suitable for active aero devices; it shall be driven only from the safety_guard stage. The implementation shall be fully synthesizable for FPGA, use only small registers/FSMs/compare logic/arithmetics, and shall not infer bulk storage arrays for payloads. All payload-bearing communication shall remain on the bounded streaming bus or control/status window. Timing closure should be friendly to modest FPGA targets by keeping datapaths narrow, using registered handshakes, and separating request packaging, monitoring, and safety arbitration into distinct pipeline stages. The architecture shall support the architecture-definition mode and cpu_reference deployment path, with the external surrogate executed in software/GPU and the RTL acting as the deterministic control wrapper.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
