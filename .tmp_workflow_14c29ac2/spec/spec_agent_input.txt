Implement a synthesizable FPGA RTL top module named adaptive_aero_control_top. The module shall provide a compact control-and-supervision wrapper around an external CPU/GPU-based aerodynamic surrogate service. The RTL shall not implement the physics model, neural network, CFD solver, or any tensor processing. The RTL top shall expose only: clock/reset, a small 32-bit register-mapped configuration/status window, one outbound request streaming interface, one inbound response streaming interface, and final actuator/status outputs.

Functional requirements:
1. Control FSM
- On reset, initialize all state, clear faults, and drive safe fallback command.
- Support idle, request_issue, wait_response, validate_response, apply_command, fallback, and fault_latched states.
- Issue a request only when the system is armed and the previous transaction is complete.
- Track a monotonically increasing sequence number and embed it in each request.

2. Request packing
- Pack request metadata into a single bounded stream word of no more than 128 bits; the recommended implementation width is 96 bits.
- Include at minimum: request opcode, sequence number, geometry reference ID, stream velocity setpoint, mode bits, and reserved fields.
- Do not include raw STL geometry, meshes, flow fields, or pressure grids in RTL.
- If the architecture requires geometry reference selection, use a small integer reference ID and optional size/hash metadata only.

3. Response validation
- Accept only responses with matching sequence number, valid flag asserted, and response status indicating completion.
- Detect stale data using either sequence mismatch, age counter exceeding threshold, or timeout expiry.
- If the response is invalid, malformed, or late, transition to fallback and assert the corresponding fault bit.
- The response stream shall also be bounded to no more than 128 bits; recommended width is 96 bits.

4. Safety clamping and fallback
- Before driving actuator outputs, clamp the command to programmable min/max limits stored in configuration registers.
- Provide a deterministic safe fallback command for all fault conditions, including stale data, timeout, and response integrity errors.
- The safe fallback command shall be configurable but default to a conservative, vehicle-safe state.
- A fault-latched mode shall be provided so software can diagnose and clear faults explicitly.

5. Configuration/status register window
- Expose a compact memory-mapped register set no wider than 64 bits per addressable access.
- Registers shall include: enable/arm, timeout threshold, min clamp, max clamp, safe fallback command, sequence seed, operating velocity, fault clear, and read-only status bits.
- Register accesses shall be synchronous, synthesizable, and suitable for an FPGA soft-CPU or external host interface.

6. Buffering and timing
- Use shallow FPGA-compatible buffering for request/response decoupling if needed; implement this with FPGA BRAM abstractions, not with a Sky130 macro.
- Add watchdog timeout logic sized by configuration registers.
- Provide backpressure via valid/ready on both streams.

7. Output behavior
- Drive actuator_cmd with the clamped proposed command when the response is fresh and valid.
- Drive actuator_cmd with the safe fallback command whenever fallback is active or a fault is detected.
- Assert actuator_valid only when the output is safe to use.
- Provide fault_flags encoding for stale reject, timeout, malformed response, clamp saturation, fallback active, sequence error, and configuration error.

8. FPGA implementation constraints
- This is an FPGA-only path; do not instantiate Sky130 SRAM hard macros.
- Use FPGA BRAM, distributed RAM, or registers only for small control/state buffering as appropriate to the target fabric.
- Keep the overall top-level scalar-equivalent I/O count below 256.
- Keep logic modular and timing-friendly for standard FPGA synthesis.

9. Software/firmware interaction
- Software running on the onboard CPU or attached host is responsible for executing the NVIDIA DoMINO Automotive Aero surrogate and returning a command proposal.
- RTL is responsible for transport, buffering, validation, timeout detection, actuator clamping, and safe fallback only.
- The design must remain correct even when no surrogate result is returned, since inference_status is not_executed in the evidence.

10. Synthesizability
- Use synchronous state elements and combinational next-state logic only.
- Avoid latches, inferred giant memories, or unsupported constructs.
- Ensure all outputs have defined reset values and all FSM branches are complete.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
NO COMMAND FALLBACK CONTRACT (mandatory; overrides conflicting generated prose): do not create a fallback command, fallback register, fallback status, fallback controller, substitute command, or fallback-on-reset behavior. On invalid, stale, timeout, reset, or fault conditions, inhibit/deassert actuator output validity and latch the fault for software handling. Do not silently replace the requested command.
