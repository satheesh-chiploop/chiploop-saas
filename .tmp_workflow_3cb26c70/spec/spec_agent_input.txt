The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.
Top module: adaptive_aero_control_top.

This design is an FPGA-targeted digital-IP wrapper for an external physics surrogate service used in an intelligent active-aerodynamics controller. The RTL shall not implement NVIDIA DoMINO inference, geometry meshing, CFD, tensor math, or any surrogate payload processing. RTL responsibilities are limited to request/response transport, configuration, validation, freshness checking, timeout handling, command limiting, actuator drive, and safe fallback.

Interface requirements:
1) The top level shall use a compact, implementation-friendly interface. A register-mapped control/status window is preferred. If streaming is used, the interface shall be bounded and no wider than 128 bits with valid/ready handshakes. The design shall not expose flow fields, surface pressure maps, geometry arrays, or other high-dimensional payloads on top-level pins.
2) The design shall include clock and active-low reset inputs.
3) The design shall include a compact register file with at least the following host-visible fields: enable, clear_fault, mode select, velocity input, timeout threshold, minimum command, maximum command, slew limit, request sequence number, status, and sticky fault.
4) The design shall include a compact request bus carrying only bounded scalar metadata required by the external surrogate service, such as sequence number, geometry handle, operating velocity, and flow-condition summary. The request bus shall not exceed 128 bits.
5) The design shall include a compact response bus carrying only bounded scalar outputs needed for control, such as validated drag summary, lift summary, response sequence number, validity flag, and age/timeout indicators. The response bus shall not exceed 128 bits.

Functional requirements:
1) On reset, the controller shall enter safe fallback mode and deassert act_valid.
2) When enabled, the controller shall accept a host request only if the request interface is ready and the configuration is valid.
3) The request_packer FSM shall capture the control inputs and emit a single bounded request descriptor for the external software/GPU runtime.
4) The response_parser FSM shall accept a returned descriptor and extract only scalar control-relevant fields.
5) The freshness_monitor shall track outstanding request sequence number and elapsed cycles since request issuance.
6) If no valid response arrives before timeout_threshold, the design shall set fault, reject the stale transaction, and force safe fallback mode.
7) If response sequence number mismatches the outstanding request, the design shall reject the response and set fault.
8) If response validity is false or malformed, the design shall reject the response and set fault.
9) The command_clamper shall saturate the commanded actuator value to the configured min/max range and apply any slew limit before output.
10) The safe_fallback_manager shall drive a deterministic conservative aero mode whenever a fault is asserted, the controller is disabled, or the host clears enable.
11) The actuator_output_if shall present act_cmd, act_mode, and act_valid using synchronous logic only.
12) The telemetry_status block shall expose sticky fault, last accepted sequence number, last valid response age, and current operating mode.
13) The design shall provide host-clearable sticky fault behavior; clear_fault shall clear sticky fault only when no active fault condition persists.
14) All control and status state shall be implemented with small registers and FSMs. No bulk payload storage shall be inferred in flip-flops. For FPGA implementation, any buffering beyond simple control state shall use the platform BRAM abstraction if needed; however, the preferred architecture is stateless transport with no deep buffering.
15) The design shall contain no dependence on a Sky130 ASIC macro for the FPGA path.
16) The design shall be synthesizable Verilog/SystemVerilog suitable for Arch2RTL translation, with explicit widths and reset behavior, deterministic state machines, and no unsized arithmetic.

Safety requirements:
- Reject stale model commands.
- Clamp actuator commands.
- Provide a safe fallback.
- Never allow an unverified response to reach actuator outputs.
- Keep faults sticky until explicitly cleared under safe conditions.

Timing and implementation guidance:
- Use single-cycle or small bounded-latency handshakes for cfg_valid/cfg_ready, req_valid/req_ready, and resp_valid/resp_ready.
- Use synchronous, edge-triggered logic for registers and FSMs.
- Keep the top-level scalar-equivalent I/O count below 256.
- Prefer fixed-point arithmetic for command values and age counters.
- The RTL shall not include the surrogate model itself; the external software/GPU service is assumed to provide the physics estimate.

Expected external system behavior:
- A host CPU or GPU worker executes the DoMINO surrogate using the provided geometry handle and flow conditions.
- The RTL receives only compact transaction metadata and scalar response summaries.
- The controller outputs a bounded actuator command to the active-aerodynamics mechanism and falls back safely on stale or invalid data.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
