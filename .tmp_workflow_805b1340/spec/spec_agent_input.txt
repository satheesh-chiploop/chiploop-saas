The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.

FIRMWARE CONTROL-PLANE CONTRACT (mandatory): this product journey requests generated firmware. The synthesizable top must expose a real firmware-visible CSR/MMIO interface with address, write-data, read-data, transaction-valid/write-enable, and response/ready semantics. DIGITAL_SPEC_JSON.register_contract must describe the implemented registers and fields. Every declared register must be reachable through RTL decode; do not label inaccessible internal state as software-visible. The streaming transport may coexist with, but cannot replace, this interface.
Design a synthesizable FPGA digital-IP controller named adaptive_aero_control_top for intelligent active aerodynamics. The RTL shall not implement the DoMINO surrogate physics model; it shall only manage request/response transport, validation, buffering, freshness checking, timeout handling, actuator command generation, and safe fallback.

Top-level interface requirements:
- Use clk and rst_n as the only clock/reset pins.
- Provide one bounded inbound streaming interface ctrl_stream_in with valid/ready and a 128-bit payload.
- Provide one bounded outbound streaming interface ctrl_stream_out with valid/ready and a 128-bit payload.
- Provide an optional cfg_csr register window no wider than 64 bits for configuration and status.
- Provide registered actuator outputs aero_actuator_cmd[15:0], aero_actuator_valid, and aero_safe_mode.
- Do not expose geometry arrays, flow fields, tensors, or bulk surrogate payloads as top-level pins.

Functional partitioning:
1) Ingress adapter shall accept a request packet containing at minimum request_id, stream_velocity_mps, mode_select, geometry reference identifier, timeout setting, and command policy fields packed into 128 bits. The packet format may be implementation-defined but shall be fixed and documented in RTL comments.
2) Flow condition decoder shall validate stream_velocity_mps against the approved operating envelope of 20 to 55 m/s. Requests outside the envelope shall be marked invalid and forced to safe fallback behavior.
3) Geometry handle router shall accept only a compact geometry reference or descriptor. The RTL shall not carry STL content or geometry arrays internally beyond small metadata fields.
4) Surrogate transaction manager shall sequence a single outstanding transaction or a bounded number of outstanding transactions as configured by small CSR bits. It shall assert a dispatch request to the external software/GPU service through the outbound stream and accept a response on the inbound return path.
5) Freshness and timeout monitor shall track request_id, response_id, issue time, response age, and outstanding count. It shall assert stale_flag if a response arrives after its configured freshness window or if response_id does not match the active request_id. It shall assert timeout_flag when the timer expires before a valid response is received.
6) Response validator shall accept only responses containing compact summary fields such as drag_force, lift_force, status_code, and actuator hint. It shall check for protocol sanity, response sequence match, and acceptable numeric ranges. It shall reject malformed or out-of-range values.
7) Analytical reference block shall compute a transparent baseline estimate using the CPU reference policy described by the requirements. The implementation may be a simple fixed-point approximation and is intended for plausibility checking and fallback selection, not surrogate replacement.
8) Actuator command planner shall translate validated aerodynamic intent into a clamped command output. The command shall be rate-limited if enabled by configuration and shall be clamped to programmed limits every cycle.
9) Safe fallback supervisor shall force aero_safe_mode high and drive a deterministic safe actuator command whenever stale data, timeout, invalid protocol, invalid range, internal overflow, or missing response is detected. Safe fallback shall dominate all other logic.
10) Status and telemetry registers shall expose current state, last error code, transaction counters, freshness flags, and configuration status.

Protocol and sequencing:
- The design shall support at least one request in flight and shall not depend on the surrogate returning in a fixed latency.
- Each request shall carry a monotonically increasing sequence number or equivalent transaction identifier.
- A response shall be accepted only if its identifier matches the active request and it arrives before timeout.
- Duplicate, replayed, or out-of-order responses shall be ignored and logged in status registers.
- The controller shall remain in safe fallback until a valid response has been received and validated after reset.
- The controller shall deassert actuator_valid when outputs are stale, invalid, or in fallback transition.

Implementation constraints for FPGA:
- Use FPGA-friendly RTL only.
- Any small buffering needed for control, status, or transaction bookkeeping may be implemented using FPGA BRAM or distributed RAM abstractions appropriate for the target toolchain.
- Do not instantiate Sky130 SRAM macros in the FPGA path.
- Keep scalar-equivalent top-level I/O below 256.
- Keep all datapaths bounded and fixed-width.
- Use synchronous reset handling for all stateful logic.
- Register all outputs that drive external pins.

Safety behavior:
- Default state after reset is safe fallback.
- Safe fallback command shall be a deterministic preset defined by configuration, typically the least aggressive aerodynamic position allowed by the actuator policy.
- Clamp all actuator outputs regardless of source.
- Reject stale model commands, invalid responses, and timeouts.
- If the external model service is unreachable, the controller shall continue issuing safe fallback only.

Non-goals:
- Do not synthesize the DoMINO model in RTL.
- Do not implement GPU kernels, large matrix operators, CFD solvers, or geometry meshing in hardware.
- Do not infer ASIC payload SRAMs; this architecture is FPGA-targeted and requires no Sky130 collateral.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
