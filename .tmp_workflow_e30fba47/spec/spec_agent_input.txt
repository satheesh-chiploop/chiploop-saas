Design a synthesizable FPGA digital IP top module named adaptive_aero_control_top for an intelligent active-aerodynamics controller. The module shall integrate a PicoRV32 soft CPU subsystem over a 32-bit Wishbone slave register interface and shall not expose any geometry, tensor, or flow-field payloads at the top level.

Top-level ports shall be limited to clk_i, rst_ni, a Wishbone slave interface (adr_i[31:0], dat_i[31:0], dat_o[31:0], sel_i[3:0], cyc_i, stb_i, we_i, ack_o, err_o optional), a compact actuator output interface, a compact status input interface, and an interrupt output. The design must keep total scalar-equivalent I/O well below 256.

The RTL shall implement the following register map at 32-bit word granularity:
- 0x00 CTRL: bit0 enable, bit1 clear_fault, bit2 arm_fallback_override, bit3 irq_enable, bits[31:8] reserved.
- 0x04 STATUS: bit0 active, bit1 fallback_active, bit2 stale_reject, bit3 timeout_fault, bit4 clamp_event, bit5 cmd_valid, bits[31:8] fault counters/status summary.
- 0x08 CMD_SEQ: last written command sequence number.
- 0x0C CMD_AGE_MAX: maximum allowed age in cycles or control ticks before stale rejection.
- 0x10 ACT_MIN0: packed minimum limits for primary actuator channels.
- 0x14 ACT_MAX0: packed maximum limits for primary actuator channels.
- 0x18 ACT_CMD0: requested actuator command word from software.
- 0x1C ACT_CMD1: optional secondary actuator command word if needed.
- 0x20 SAFE_STATE0: packed safe fallback actuator command word.
- 0x24 VEH_SPEED: compact vehicle-speed/status input sample in fixed-point format.
- 0x28 FAULT_CODE: latched fault code; writing clear_fault clears latched faults.
- 0x2C IRQ_STATUS: write-1-to-clear event bits for timeout, stale, clamp, and accepted-command interrupts.
- 0x30 VERSION: module version and compatibility fields.

Wishbone behavior: ack_o shall assert for a single cycle on accepted reads/writes. Invalid addresses may return zero and assert err_o if implemented. Writes shall update control registers synchronously on clk_i. Reads shall return registered or combinationally multiplexed data with no multi-cycle dependency beyond one bus cycle.

Command acceptance logic: software shall publish a new command by writing ACT_CMD0/ACT_CMD1, CMD_SEQ, and enabling CTRL.enable. The hardware shall compare the incoming sequence number against the stored last accepted sequence. A command is accepted only when enable is high, the sequence is strictly newer, and the command has not exceeded CMD_AGE_MAX. On acceptance, the module updates last-accepted sequence, clears stale flags, and forwards the clamped command to the actuator output register.

Stale-data detection: a cycle counter or control-tick counter shall increment while enabled. If the elapsed age since the last accepted sequence exceeds CMD_AGE_MAX, assert stale_reject, latch FAULT_CODE, set fallback_active, and force SAFE_STATE0 to the actuator output. The design shall not assume surrogate inference results; it only supervises software-issued commands.

Timeout handling: if no valid command refresh occurs within the configured age threshold, or if software disables control, the module shall transition to safe fallback. Fallback remains active until CTRL.clear_fault or a valid new command sequence is accepted, subject to arm_fallback_override policy if implemented. The safe fallback output must be deterministic and reset-defined.

Clamping: each actuator field shall be independently clamped between configured ACT_MIN0 and ACT_MAX0 limits. Any clamping shall set clamp_event and optionally raise an interrupt when irq_enable is set. Clamped values shall be the only values driven to actuator_cmd outputs.

Interrupts: irq_o shall pulse or level-assert on accepted command, stale reject, timeout, or clamp event according to IRQ_STATUS and CTRL.irq_enable. Interrupt status bits shall be sticky until cleared by write-1-to-clear.

Optional buffering: if a packet buffer is needed for software/hardware decoupling, implement it only with FPGA BRAM or vendor-native RAM inference appropriate for the FPGA target. Do not implement bulk payload storage with flip-flops or inferred ASIC SRAM structures. No Sky130 hard macro shall be used in the FPGA implementation path.

Reset behavior: upon rst_ni deassertion, the module shall load SAFE_STATE0 as the initial actuator output, clear command age and fault latches, deassert active, and keep fallback_active asserted until a valid command is accepted and enable is set.

Timing and synthesis: all sequential logic shall be clocked by clk_i. All outputs shall be registered or derived from registered state to support straightforward FPGA synthesis at the specified system clock. The design should be written in clean synthesizable RTL with explicit FSMs, counters, comparators, and packed register fields only.
