The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.

FIRMWARE CONTROL-PLANE CONTRACT (mandatory): this product journey requests generated firmware. The synthesizable top must expose a real firmware-visible CSR/MMIO interface with address, write-data, read-data, transaction-valid/write-enable, and response/ready semantics. DIGITAL_SPEC_JSON.register_contract must describe the implemented registers and fields. Every declared register must be reachable through RTL decode; do not label inaccessible internal state as software-visible. The streaming transport may coexist with, but cannot replace, this interface.
Module adaptive_aero_control_top shall be a synthesizable FPGA digital-IP top level for an intelligent active-aerodynamics controller. The RTL shall not implement the NVIDIA DoMINO surrogate model, do not infer tensors, geometry arrays, surface pressure fields, or flow fields in hardware, and shall not require GPU execution. The module shall provide a compact bounded streaming interface using valid/ready handshakes with cmd_in_data[127:0] and status_out_data[63:0]. The module shall accept host-provided request metadata and control targets, validate them, track freshness using sequence/epoch counters, reject stale or malformed commands, and generate sanitized actuator commands. Internal storage shall be limited to small control/status registers, counters, sticky fault bits, and FSM state; bulk payload buffering shall not be implemented as flip-flop arrays. The design shall include: 1) input packet capture and decode logic; 2) request validity checking; 3) freshness monitor with programmable timeout counter; 4) stale-command rejection; 5) safe fallback state machine; 6) actuator command clamping against programmable min/max bounds; 7) optional simple slew-rate limiting if enabled by control register; 8) status/telemetry packet generation; and 9) fault interrupt generation. Default active state shall pass only validated commands. On timeout, sequence discontinuity, malformed packet, or explicit fault, the FSM shall drive a safe fallback actuator command and set sticky fault status. The design shall expose readable control/status registers sufficient to configure timeout threshold, clamp limits, mode enable, and acknowledge sticky faults. The RTL shall be fully synchronous to clk with rst_n reset behavior and shall use no top-level bus wider than 128 bits. For FPGA implementation, use FPGA-appropriate memory primitives only if needed for small register-visible storage; do not use Sky130 macros. The module shall be sized for onboard CPU deployment with low scalar-equivalent I/O count and no dependence on external model inference hardware. The packet format shall include at minimum: command_valid, command_mode, sequence counter, freshness token or age tag, actuator target fields, and host acknowledgment fields. Status shall report acceptance/rejection cause, stale flag, watchdog expired flag, fallback-active flag, clamp-applied flag, current mode, and last accepted sequence. All outputs to actuators shall be sanitized before use.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
NO COMMAND FALLBACK CONTRACT (mandatory; overrides conflicting generated prose): do not create a fallback command, fallback register, fallback status, fallback controller, substitute command, or fallback-on-reset behavior. On invalid, stale, timeout, reset, or fault conditions, inhibit/deassert actuator output validity and latch the fault for software handling. Do not silently replace the requested command.
