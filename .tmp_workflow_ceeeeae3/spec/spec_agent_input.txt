The required synthesizable top module is motor_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must retain the motor-control request/response, safety, timeout, and actuator-command behavior.
Design a synthesizable ASIC digital IP named DoMINO_AeroSafe_Controller that wraps a pretrained external automotive-aerodynamics model service. The RTL shall not implement physics inference, neural network layers, tensor math, or surrogate-model internals. The IP shall provide: (1) a compact CSR-based control/status plane, (2) a request packager that constructs bounded service requests from host-provided geometry descriptors and flow conditions, (3) a transport controller with valid/ready handshakes to an external GPU-hosted model service, (4) freshness and timeout supervision, (5) command clamping, and (6) a safe fallback actuator state machine.

Top-level interface requirements:
- The top level shall use either a 64-bit-or-narrower register window or a bounded streaming bus no wider than 128 bits. No top-level geometry arrays, tensors, mesh nodes, flow fields, or per-point payload pins are permitted.
- The preferred top-level interface is a 64-bit CSR window with addr, wdata, rdata, we, re, valid, ready, and byte enables.
- The design may include a 128-bit request stream and a 128-bit response stream for transport bridging, each with valid/ready.
- The estimated scalar-equivalent top-level I/O count shall remain below 256.

Functional requirements:
- The host shall write configuration registers for model checkpoint/version tag, velocity operating point, timeout threshold, actuator min/max limits, slew-rate limit, geometry base address, geometry length, and control flags.
- The design shall accept a start event with seq_id and cmd_age_ticks. The request packager shall generate a descriptor containing seq_id, geometry pointer, geometry length, geometry format tag, stream velocity, and a service opcode.
- The payload_pointer_manager shall only store pointers, sizes, format tags, and alignment checks. It shall not store the full STL geometry in flip-flops.
- The transport controller shall issue a request when the host asserts start, configuration is valid, and no fault is pending. It shall wait for a response with ready/valid handshakes. If the response does not arrive before timeout expiration, assert timeout fault and invoke fallback.
- The freshness_timeout_supervisor shall reject stale commands when cmd_age_ticks exceeds the configured freshness threshold or when seq_id is not newer than the last accepted sequence number.
- The response parser shall accept only bounded fixed-format responses containing command-relevant fields. Because the surrogate outputs drag_force, lift_force, surface_pressure, and flow_field, the RTL shall use only a compact command extraction field defined by system integration; it shall not surface full flow fields or pressure maps at top level.
- The command_clamper shall apply min/max saturation and slew-rate limiting to produce actuator_cmd_out.cmd_value and cmd_rate.
- The safe_fallback_controller shall drive a deterministic safe aerodynamic setting on any fault, timeout, stale input, malformed response, host abort, or transport error.
- The actuator command formatter shall assert cmd_valid only when no safety violation is active. When fallback is active, safe_mode shall be asserted and fault shall be sticky until cleared by host software.
- The design shall provide sticky status bits for busy, done, fault, timeout, stale, clamped, fallback_active, transport_error, and response_valid.

Register map requirements:
- Implement a small set of CSRs only; bulk data storage is external.
- Required registers include control, status, seq_id, timeout, freshness_limit, velocity_mps, geometry_base_addr, geometry_length, geometry_format, actuator_min, actuator_max, slew_limit, checkpoint_id, launch, clear_fault, and response summary.
- Reads shall return deterministic status values; writes shall update configuration only when valid and not busy, except clear_fault which may clear sticky fault bits when safe.

ASIC memory requirements:
- Do not infer bulk payload storage using reg arrays, distributed RAM, generic SRAM wrappers, BRAM inference, or FIFO register banks.
- If internal buffering of payload descriptors beyond small control state is required, the implementation shall use the Sky130 hard macro sky130_sram_1kbyte_1rw1r_32x256_8 only, with ports clk0, csb0, web0, wmask0[3:0], addr0[7:0], din0[31:0], and dout0[31:0].
- Multiple macro instances may be banked only if needed for descriptor storage capacity.
- Before any Sky130 ASIC implementation that uses the macro, the behavioral Verilog, Liberty, LEF, GDS, and SPICE collateral for sky130_sram_1kbyte_1rw1r_32x256_8 must be available and checked in at the integration gate. If any collateral is missing, the flow shall stop at the memory-collateral gate and shall not remap storage into standard-cell registers.

State machine requirements:
- Implement at minimum IDLE, ISSUE_REQ, WAIT_RSP, VALIDATE, CLAMP, APPLY, FALLBACK, and FAULT states.
- All state transitions shall be synchronous to clk and reset-safe.
- The design shall be free of combinational loops and shall register outputs before external handoff where required by timing closure.
- The design shall use explicit handshaking and acknowledge paths for host and transport interfaces.

Safety and reliability requirements:
- Any malformed payload descriptor, unsupported geometry format, illegal velocity setting, or transport protocol error shall force fallback and fault indication.
- The design shall not rely on the correctness of the remote model for safety. Safety enforcement shall be local in RTL.
- The design shall clamp outputs regardless of response content.
- The design shall reject stale model commands and mismatched sequence IDs.
- The design shall support a watchdog/timeout configurable in ticks.
- The design shall preserve last-safe output or a predefined safe-state output on fault.

Implementation constraints:
- Synthesize as digital IP suitable for Arch2RTL conversion.
- Use only standard-cell logic for control, compare, arithmetic, FSM, and small registers.
- Do not instantiate floating-point physics, geometry processing, or full STL parsing in RTL; only handle descriptors, sizes, and tags.
- Do not add undocumented top-level ports. Keep the interface compact and implementation-friendly.
- No inference-based payload memories are allowed in ASIC flow unless explicitly mapped to the approved Sky130 macro after collateral validation.
ASIC MEMORY CONTRACT (mandatory): instantiate sky130_sram_1kbyte_1rw1r_32x256_8 for bulk payload/history/FIFO storage using clk0, csb0, web0, wmask0[3:0], addr0[7:0], din0[31:0], and dout0[31:0]. Do not expand payload, history, FIFO, or telemetry storage into individually named registers, flip-flop arrays, or inferred memories. Small control/status registers are allowed.
