The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.
Module name: adaptive_aero_control_top.

Purpose: Synthesizable FPGA control IP for an intelligent active-aerodynamics controller that mediates between host/software-based DoMINO inference and vehicle actuators. The RTL shall not implement neural inference, CFD, geometry processing, or surrogate tensor math. The RTL shall implement configuration, request/response transport, stale-data detection, timeout handling, command clamping, fallback selection, and actuator command issuance.

Top-level ports:
- clk, rst_n or clk/rst pair.
- cfg_reg_if: compact memory-mapped window, 32-bit data path recommended. Use small address space only for control/status registers, timeout values, sequence tracking, clamp min/max, and mode select.
- req_stream: valid/ready output stream, maximum width 128 bits.
- rsp_stream: valid/ready input stream, maximum width 128 bits.
- actuator_cmd: valid/ready output stream, maximum width 64 bits.
- telemetry_out: valid/ready output stream, maximum width 32 bits.

Functional requirements:
1. On reset, drive safe defaults and assert no actuation until configuration is complete.
2. Collect control inputs from configuration registers and local state to form a compact inference request. Request fields may include mode, current velocity estimate, setpoint, sequence number, and request flags; do not include geometry payloads.
3. Assert req_stream_valid only when a request is ready and downstream ready is observed or buffered according to a shallow control FIFO implemented as control-state only, not bulk payload storage.
4. Accept rsp_stream payload only when valid/ready handshake succeeds. Response payload must carry compact command candidate, sequence number, age tag, and validity tag.
5. Implement freshness checking using sequence comparison and timestamp/age thresholds. A response is stale if it exceeds the configured timeout or if it does not match the latest outstanding request sequence.
6. Implement clamp logic that limits every actuator component to configured min/max bounds. If slew-rate limiting is enabled, constrain delta between consecutive commands.
7. If any safety check fails, select fallback_manager output and indicate fault in telemetry.
8. Actuator command outputs shall be deterministic under all conditions and shall never exceed configured limits.
9. Telemetry shall report mode, active fault code, stale-data flag, timeout flag, clamp-activity flag, and fallback-active flag.
10. No inferred bulk memories for payload storage. For FPGA implementation, if temporary buffering is required, use the platform's BRAM abstraction only for bounded request/response staging, and keep the buffer depth small and explicitly sized.
11. Do not instantiate the NVIDIA surrogate or attempt to process vehicle geometry or flow fields in RTL.
12. Provide parameterization for timeout threshold, response window, command clamps, and optional slew limit.
13. Maintain scalar-equivalent top-level I/O count below 256.

Interface semantics:
- req_stream payload is application-defined compact metadata only.
- rsp_stream payload contains compact control candidates and sequence metadata only.
- actuator_cmd payload carries final bounded aero actuator positions or setpoints.
- telemetry_out carries compact status words for host supervision.

Implementation notes:
- Use synthesizable FSMs, comparators, counters, and small register banks.
- Use signed arithmetic for command clamping if actuator coordinates require it.
- Use one-hot or encoded state machine as preferred by FPGA flow.
- Avoid asynchronous combinational feedback across valid/ready interfaces.
- Include explicit error latching and clear-on-read or clear-on-write behavior for status bits as parameterized options.
- If a buffered request/response path is implemented, it shall be shallow and bounded; do not use large register arrays or generic inferred memories for payload storage.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
