Design a synthesizable FPGA digital IP top module named adaptive_aero_control_top that implements a real-time active-aerodynamics controller supervisor for an external NVIDIA DoMINO Automotive Aero software/GPU reference service. The RTL shall not implement the surrogate model, geometry processing, CFD, or any tensor computation. The RTL shall provide: (1) a compact inbound request channel using valid/ready handshake, payload width <= 128 bits; (2) a compact outbound response channel using valid/ready handshake, payload width <= 128 bits; (3) a register-mapped control/status window using <= 64-bit data path; (4) timeout, freshness, sequence, and integrity checking; (5) actuator command clamping and safe fallback; (6) optional bounded buffering for a small number of outstanding messages; and (7) explicit fault/status reporting.

Top-level ports shall be implementation-friendly and avoid exposing vehicle_geometry, flow_fields, surface_pressure arrays, or any surrogate payload as a large pin set. The preferred top-level interface shall be a packed streaming bus plus a small CSR window. The control/status register block shall include at minimum: enable, mode_select, timeout_limit, stale_limit, min_actuator_cmd, max_actuator_cmd, slew_limit, request_seq_seed, last_seq_seen, fault_status, fallback_active, and output_command registers. Reads and writes shall be synchronous and single-cycle or wait-stated as required by the chosen FPGA bus wrapper.

The control FSM shall contain at least the following states: RESET, IDLE, ISSUE_REQUEST, WAIT_RESPONSE, VALIDATE_RESPONSE, APPLY_COMMAND, SAFE_FALLBACK, and FAULT_HOLD. On reset, outputs shall drive the safe fallback value and fault flags shall be cleared only after configuration and enable are valid. On enable, the controller shall package a request message including sequence number, timestamp or age token, selected velocity operating point, and a geometry reference handle or ID. Since the supplied execution evidence states inference_status = not_executed, the RTL shall treat any response as originating from an external reference path and shall never assume validated predictions are available at reset.

Protocol checks shall include: sequence match, response age within timeout_limit, no underflow/overflow in packet length fields, optional checksum or parity if provided by the surrounding system, and valid response opcode. If any check fails, the module shall assert fault_status and transition to SAFE_FALLBACK. In safe fallback, the actuator output shall be clamped to a programmable safe value or a defined minimum-risk state, and remain there until the host clears faults and re-enables the controller.

Actuator command generation shall be bounded and monotonic where applicable. If the command is a flap angle or similar setpoint, implement signed or unsigned saturation logic based on programmed min/max limits and optional slew limiting relative to the previous accepted command. The design shall never emit an out-of-range command. If the response suggests a command outside programmed limits, the module shall clamp it and set a clamp_event status bit.

If message buffering is required, implement only a small bounded queue suitable for FPGA BRAM; do not infer a large register-file payload store. The implementation shall be portable across FPGA devices and shall use vendor BRAM inference or explicit FPGA BRAM primitives as needed. Do not instantiate Sky130 hard macros in the FPGA path.

The design shall maintain less than 256 scalar-equivalent I/O by construction. The external request/response bus width shall remain compact and implementation-friendly. The module shall provide deterministic latency for protocol handling, with timeout behavior governed by programmable cycle counters. All control registers, counters, and FSM state shall be synthesizable in standard RTL. Any software-facing model execution happens outside RTL on CPU/GPU; the FPGA only supervises transport, validation, and actuation.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
NO COMMAND FALLBACK CONTRACT (mandatory; overrides conflicting generated prose): do not create a fallback command, fallback register, fallback status, fallback controller, substitute command, or fallback-on-reset behavior. On invalid, stale, timeout, reset, or fault conditions, inhibit/deassert actuator output validity and latch the fault for software handling. Do not silently replace the requested command.
