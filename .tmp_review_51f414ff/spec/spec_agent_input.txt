The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.
Implement a synthesizable FPGA top module named adaptive_aero_control_top with a compact control-plane interface. The design shall not instantiate or implement the NVIDIA DoMINO surrogate model in RTL. Instead, it shall provide a bounded transport wrapper for request/response exchange with an external CPU/GPU reference service and shall enforce local safety before actuator drive-out.

Port requirements:
- clk, rst_n.
- One 128-bit valid/ready input stream for inbound command/response packets.
- One 128-bit valid/ready output stream for outbound status/request packets.
- A small register-memory window interface with 8-bit address and 32-bit data, using cfg_addr, cfg_wdata, cfg_rdata, cfg_we, cfg_re.
- Actuator output interface limited to compact scalar command signals, not tensor/geometry payloads.

Packet handling:
- Define an internal packet format within 128 bits sufficient for sequence number, timestamp or age counter, command field, validity flags, error flags, and optional request descriptor handle.
- The packetizer shall assemble outbound requests from configuration registers and latest control inputs.
- The depacketizer shall unpack inbound responses and present a compact actuator command candidate plus metadata to the safety pipeline.
- Support backpressure using valid/ready on both streams.

Safety and control policy:
- Maintain a monotonically increasing request sequence counter.
- Store the last accepted sequence and compare each inbound response to reject duplicates and out-of-order packets.
- Implement an age counter and watchdog timer programmed via registers. If response age exceeds the threshold, assert timeout and move to fallback.
- Implement stale-data detection using packet timestamp/age comparison and/or sequence mismatch. Any stale packet shall be ignored and reported.
- Implement clamp logic for actuator_cmd using programmable min and max limits. If rate-limit enable is set, constrain step size versus the prior accepted command.
- Implement a fallback FSM with states such as IDLE, ARMED, ACTIVE, TIMEOUT_FALLBACK, and FAULT_HOLD. Fallback output shall be deterministic and safe.
- On reset, force actuator_cmd_valid low and output the configured safe fallback command or a conservative default.

Configuration registers:
- Include registers for enable, safe fallback command, min/max clamp limits, rate limit, timeout threshold, stale threshold, status flags, fault counters, and optional debug counters.
- Register reads shall return current values and latched fault status.
- Register writes shall update parameters atomically per register access.

Storage implementation:
- For FPGA implementation, use platform BRAM inference or an FPGA BRAM abstraction only for small telemetry/history storage if needed.
- Do not infer large payload memories or FIFO arrays using flip-flops.
- Do not use Sky130 hard macros in the FPGA path.

External integration:
- The external software/GPU service is responsible for running the CPU reference path or future surrogate inference. The RTL only forwards compact requests and receives compact responses.
- The geometry input is treated as an opaque descriptor or preloaded handle; STL meshes and flow fields are not exposed as top-level ports.
- Provide status reporting so firmware can log whether a request was issued, a response was received, a clamp occurred, a timeout occurred, or fallback was engaged.

Timing and synthesis:
- All sequential logic shall be clocked by clk and reset by rst_n.
- Combinational next-state logic shall determine output valid and safety decisions.
- The design shall be deterministic, single-clock, and FPGA-synthesizable with no unsized arithmetic, no unsynthesizable system tasks, and no behavioral dependence on the external surrogate.
- Top-level scalar-equivalent I/O count shall remain below 256.

Functional intent:
- This IP serves as the hardware control shell for intelligent active aerodynamics over 20-55 m/s vehicle operation.
- Because surrogate inference is not executed in the provided evidence, the RTL shall not encode any model prediction constants or assumed drag/lift outputs.
- The hardware must only accept validated command recommendations and enforce safe actuator operation.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
