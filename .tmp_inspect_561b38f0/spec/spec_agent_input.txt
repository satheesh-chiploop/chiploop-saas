Module name: adaptive_aero_control_top.

Target implementation: FPGA soft-CPU system using PicoRV32 with Wishbone interconnect. The RTL shall implement a control wrapper around an external software/GPU surrogate for active aerodynamics. The surrogate model itself is not implemented in RTL.

Top-level microarchitecture:
1) Instantiate a PicoRV32-compatible Wishbone master CPU subsystem.
2) Instantiate a small Wishbone-mapped register file for control/status.
3) Instantiate a compact request bridge and response bridge for model transport.
4) Instantiate stale-data, timeout, and sequence monitors.
5) Instantiate a clamp/fallback actuator controller.
6) Instantiate UART debug logic.

Interface requirements:
- Top-level bus shall use Wishbone signals compatible with PicoRV32.
- Any external model transport shall use a bounded valid/ready streaming interface with payload width <= 128 bits.
- No top-level tensor, mesh, geometry array, pressure field, or flow field ports are permitted.
- Actuator outputs shall be compact scalar command words suitable for flap/air-brake/vent control.

Register map requirements:
- Provide at least the following 32-bit registers: CTRL, STATUS, SEQ_OUT, SEQ_IN, STALE_LIMIT, TIMEOUT_LIMIT, CLAMP_MIN, CLAMP_MAX, FALLBACK_CMD, LAST_CMD, LAST_RSP_META, FAULT_CODE.
- CTRL fields shall include enable, clear_fault, arm_fallback, and request_start bits.
- STATUS fields shall include busy, request_pending, response_valid, stale_reject, timeout_fault, clamp_active, fallback_active, and fault_latched.
- FAULT_CODE shall encode stale data, timeout, sequence mismatch, malformed response, and actuator clamp events.

Model request bridge behavior:
- When software writes a request-start command and the system is enabled, capture the current sequence number and compact flow-condition summary.
- The request payload must include only scalar summaries needed by the external runtime, such as stream velocity, sequence number, geometry handle or identifier, operating mode, and versioned header.
- The bridge shall assert model_req_valid until model_req_ready is observed or until a programmable timeout expires.
- If timeout expires, set fault, mark request_pending low, and command fallback.
- The bridge shall never drive more than 128 bits of request payload.

Model response bridge behavior:
- Accept model_rsp_valid/model_rsp_data from the external runtime only when a request is pending or a response is expected.
- Extract response sequence, validity bits, and compact aerodynamic outputs such as drag summary, lift summary, and control recommendation summary.
- If the response sequence does not match the outstanding request sequence, reject it and raise a sequence fault.
- If no valid response arrives before TIMEOUT_LIMIT, assert timeout fault and command fallback.
- Do not store bulk flow fields in RTL; ignore any unsupported response content.

Safety monitor behavior:
- Maintain an age counter and a sequence counter.
- Reject stale data when response age exceeds STALE_LIMIT.
- Reject any command derived from data older than the configured age limit.
- Latch faults until a software clear_fault action is written.

Clamp/fallback actuator controller:
- Before issuing any actuator command, clamp it to [CLAMP_MIN, CLAMP_MAX].
- If fallback_active is asserted, drive FALLBACK_CMD instead of the model-derived command.
- A safe fallback shall be a conservative fixed command value defined by software configuration and shall be used on reset and on all unrecoverable faults.
- Output shall use valid/ready handshake with the downstream actuator interface.
- The controller shall not update outputs unless all safety checks pass.

Clock/reset/CDC:
- Single-clock operation is sufficient unless board integration requires a synchronizer for asynchronous external valid signals.
- Any asynchronous input shall be synchronized with at least two flip-flops before use.

Synthesis rules:
- RTL must be fully synthesizable.
- For FPGA, use BRAM abstractions only if buffering is required by the soft-CPU subsystem; do not instantiate Sky130 hard macros.
- Do not infer large register arrays for payload storage.
- Control/status registers, counters, FSM state, and small scoreboard registers are allowed.

Firmware contract:
- Software running on PicoRV32 is responsible for loading geometry handles, operating conditions, calling the external model service, and writing back the compact response metadata into the register map.
- The RTL shall validate the response metadata and enforce safety before actuator update.

Reset behavior:
- On reset: disable outputs, clear pending request, clear handshake valid signals, set actuator outputs to FALLBACK_CMD, and assert fallback_active until software re-arms the system.

Error handling:
- Any malformed response, missing ready/valid handshake, unexpected sequence, stale age, or timeout must produce a latched fault.
- Fault clear is only allowed when the system is idle and software explicitly writes clear_fault.

Observability:
- Expose minimal telemetry through STATUS, LAST_CMD, LAST_RSP_META, and FAULT_CODE registers.
- UART debug may mirror these values but shall not be required for safety.
