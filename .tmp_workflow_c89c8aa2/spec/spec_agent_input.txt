Module name: adaptive_aero_control_top.

Goal: synthesizable FPGA top-level for an intelligent active-aerodynamics controller using a soft CPU. The module shall not implement the DoMINO surrogate compute. Instead, it shall provide bounded transport, control/status registers, safety supervision, and actuator command handling.

Architecture:
1) Instantiate a PicoRV32-based subsystem connected via Wishbone.
2) Provide a memory-mapped register window accessible by the CPU. The register block shall be 32-bit wide and shall contain at minimum: control/mode, stream velocity input, max/min actuator clamp values, request sequence, request launch, response sequence, response age, fault summary, and safe-fallback configuration.
3) Implement a model transport bridge that frames compact request messages and accepts compact response messages. The bridge shall use valid/ready handshake on a bounded data path no wider than 64 bits at the top level. The bridge shall attach sequence numbers and message-length checking. No tensors, arrays, geometry buffers, or flow-field outputs shall be exposed at the top level.
4) Implement a safety supervisor in hardware. It shall compare response sequence against the outstanding request sequence, detect stale or repeated responses, detect timeout expiration, and force safe fallback on any fault.
5) Implement actuator command clamping in hardware. Any command from firmware or from the response path shall be limited to the configured minimum and maximum actuator range. The final command presented to outputs shall be the clamped value.
6) Provide a safe fallback mode. On reset, timeout, malformed response, stale response, or firmware-declared fault, the module shall drive a deterministic safe command and assert a fault flag.
7) Provide a status path back to firmware indicating busy, request accepted, response valid, response stale, timeout expired, clamp active, and safe fallback active.
8) Keep all bulk payloads off-chip or in firmware-managed memory. RTL shall not infer payload memories using reg arrays, generic SRAMs, or BRAMs for surrogate data. Only small control/state registers and FSM state are permitted in RTL.
9) The top-level port set shall remain implementation-friendly and below 256 scalar-equivalent I/O signals. Use a 32-bit Wishbone register interface plus a 64-bit maximum stream interface for model transport.
10) Timing: the safety monitor and command clamp shall be fully synchronous to clk and shall have deterministic one-cycle or registered behavior. No combinational loops between input request and output actuator command are allowed.
11) Reset: active-low reset shall initialize mode to safe fallback, clear outstanding request state, clear fault summaries, and set output-valid low.
12) Firmware interaction: firmware running on PicoRV32 shall write request metadata and read response/status registers. The hardware shall not assume the existence of a GPU inside the FPGA; the external model runtime is off-chip software/GPU.
13) For FPGA implementation, use vendor-agnostic synthesizable RTL and standard FPGA BRAM only for CPU memories if required by the selected soft CPU subsystem. Do not use Sky130 hard macros on FPGA.
14) If future ASIC reuse is desired, a separate memory-collateral gate shall be enforced before selecting any Sky130 SRAM macro. For the present FPGA path, no ASIC memory macro instantiation shall be used.

Required behaviors:
- Accept a new request only when the bridge is idle and the previous request is fully retired.
- Tag each request with an incrementing sequence counter.
- Reject any response whose sequence does not match the outstanding request.
- Reject any response arriving after timeout expiration.
- Clamp actuator commands to the configured range and set clamp_active status if clamping occurred.
- Force safe_fallback_active on reset, timeout, stale response, malformed response, or firmware fault.
- Provide one-cycle pulse or registered level on request_accepted and response_valid status signals.

Suggested internal registers:
- CTRL: mode, enable, launch, clear_faults.
- VELOCITY: encoded stream velocity input in m/s.
- CMD_MIN / CMD_MAX: actuator bounds.
- REQ_META: sequence, condition code, reserved.
- RSP_META: sequence, status, age, reserved.
- FAULT: bitfield with stale, timeout, malformed, clamp, fallback.
- OUTPUT: final actuator command and valid bit.

The module must be fully synthesizable, use only bounded-width buses, and preserve deterministic safe operation under loss of external model service.
