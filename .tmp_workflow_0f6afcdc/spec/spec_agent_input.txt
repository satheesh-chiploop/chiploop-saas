The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.
Implement a synthesizable FPGA digital IP top module named adaptive_aero_control_top. The module shall provide a compact register window and one bounded request/response streaming path to an external GPU/NIM worker that executes the pretrained DoMINO automotive-aero model in software. The RTL shall not contain any physics surrogate computation, tensor processing, geometry meshing, or flow-field inference.

Top-level ports shall be limited to clk, rst_n, an 8-bit register address, 32-bit write data, 32-bit read data, read/write strobes, a 128-bit request stream with valid/ready handshake, a 128-bit response stream with valid/ready handshake, a 32-bit actuator command output, an actuator command valid output, and a 32-bit status output. No geometry arrays, no tensor ports, and no thousands of scalar pins are permitted.

The register block shall include at minimum: enable, soft reset, sequence counter seed, request timeout threshold, maximum actuator command, minimum actuator command, fallback command, current stream velocity setpoint, flow-condition configuration fields, response age limit, and status clear controls. The reference operating point fields shall support the supplied conditions of stream_velocity_mps=38.89 and geometry_format=STL with geometry_source=DrivAerML reference geometry as configuration metadata, but the RTL shall treat geometry itself as an external payload handle or descriptor rather than storing a full geometry model on-chip.

Request_packager shall compose each outbound request into req_data using a fixed-width encoding defined by the implementation team. The payload shall include a transaction ID, sequence counter, configuration snapshot, flow-condition values, and a compact geometry descriptor or memory token. req_valid shall assert only when a request is ready and the external bridge is available; the request shall be held stable until req_ready is observed. The module shall not launch a new request while one is outstanding unless explicitly configured for pipelined mode in registers; default mode is single-outstanding-transaction.

Response_validator shall accept rsp_data only when rsp_valid is asserted and the response transaction ID and sequence match the outstanding request. The validator shall compare the response arrival time against the watchdog timer and reject stale responses. Any invalid, malformed, late, or unexpected response shall be discarded without changing the current safe command path. The validator shall also gate the transition to command_mapper on model-present and model-enabled status bits.

Command_mapper shall transform accepted model output fields into a deterministic actuator command word. The mapping shall be abstract and configuration-driven, supporting active-aerodynamics actuators such as spoiler, flap, grille shutter, or diffuser positions. The design shall not assume a specific mechanical package in the RTL; instead it shall provide a single 32-bit command word whose encoding is defined by software/integration registers.

Saturation_and_safety_gate shall clamp the command word to configured min/max bounds prior to output. If the computed command exceeds bounds, the command shall be limited to the nearest bound and a saturation status bit shall assert. If validation fails, timeout expires, enable is deasserted, or a stale response is detected, fallback_controller shall drive a deterministic safe command selected from register configuration. The fallback command shall be applied until a fresh valid response is received and accepted.

Watchdog_timer shall start on request issue and count until a valid matching response is accepted or timeout occurs. On timeout, the module shall assert timeout status, discard any later response for that transaction, and force fallback. A response age limit register may be used to implement a second stale-response check independent of the base timeout. Status telemetry shall include busy, ready-for-request, response-pending, response-accepted, validation-failed, stale-rejected, timeout, saturation, fallback-active, and enable bits.

The RTL shall be written to synthesize cleanly on FPGA. Use flip-flops only for control/state and do not infer bulk payload storage for geometry or response data. If buffering is required for a small number of requests or responses, keep it shallow and control-oriented; the architecture is intended for one outstanding transaction by default. All arithmetic shall be bounded and fixed-width. No floating-point math is required in RTL; any unit conversion or normalization beyond the fixed command mapping shall be performed externally or via preconfigured lookup values.

Reset behavior: upon rst_n deassertion, the module shall enter safe fallback state, clear outstanding transaction state, clear stale/timeout flags, and drive act_cmd_valid low until enabled and a valid command is available. Status outputs shall indicate fallback-active after reset until the first accepted response produces a valid command.

The register interface shall be sufficient for software to configure the external GPU worker session, load transaction parameters, monitor status, clear faults, and read the latest accepted command state. The design shall keep total top-level scalar-equivalent I/O under 256 and shall use standard FPGA-friendly valid/ready and register-window conventions. The implementation shall avoid any Sky130 hard macro usage because the target is FPGA prototype.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
