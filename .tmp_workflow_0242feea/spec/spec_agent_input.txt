The required synthesizable top module is motor_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must retain the motor-control request/response, safety, timeout, and actuator-command behavior.
Design a synthesizable ASIC digital IP block that wraps an external NVIDIA DoMINO automotive-aerodynamics service. The RTL shall implement a compact control-plane and transport-plane interface only; the physics/surrogate model is not part of RTL.

Top-level interface requirements:
1) Provide a clock and active-low reset.
2) Provide a 64-bit register-memory window for software control/status with signals cfg_addr[31:0], cfg_wdata[63:0], cfg_rdata[63:0], cfg_we, cfg_re, cfg_ready.
3) Provide a bounded streaming outbound request interface with tx_valid, tx_ready, and tx_data[127:0].
4) Provide a bounded streaming inbound response interface with rx_valid, rx_ready, and rx_data[127:0].
5) Provide a compact actuator command interface with act_valid, act_ready, and act_cmd[31:0].
6) Provide fault_out, busy_out, and fallback_out status pins.
7) Total scalar-equivalent top-level I/O shall remain below 256.
8) No top-level tensor buses, geometry arrays, point clouds, CFD fields, or per-node outputs are permitted.

Functional behavior:
1) On reset, initialize all registers, sequence counters, and status flags to safe values. Default actuator command shall be the configured safe-fallback command or zero if not programmed.
2) Software programs a request descriptor through the register window. Registers shall include at minimum: enable, start_request, model_id, request_seq, max_response_age, timeout_cycles, clamp_min, clamp_max, safe_fallback_cmd, request_flags, and status readbacks.
3) When start_request is asserted and the block is enabled, the RTL shall assemble a compact outbound request frame into tx_data. The frame shall contain only metadata and small scalar descriptors required by the external runtime, including model ID, sequence number, request type, geometry descriptor handle/pointer, geometry length, flow-condition scalars, and optional integrity bits. The RTL shall not attempt to process or store full geometry payloads as top-level signals.
4) tx_valid shall remain asserted until tx_ready is observed. The request shall be considered issued only on a valid/ready handshake.
5) The block shall track an expected response sequence number and deadline counter. If a response does not arrive before timeout_cycles, the block shall assert fallback_out, set fault_out, and transition to safe-fallback state.
6) When rx_valid is asserted, the RTL shall sample rx_data only when the response is expected and the block is ready. The response frame shall be interpreted as a compact recommendation/status packet from the external runtime, not as raw field data. The RTL shall verify sequence match, response type, and integrity flags/CRC/parity if present.
7) Any stale, duplicated, malformed, or sequence-mismatched response shall be rejected. Such rejection shall set a sticky fault bit and force safe fallback.
8) The output actuator command shall be derived only from approved response metadata or from safe fallback. The command path shall include a clamp stage that limits the command to clamp_min..clamp_max. If slew limiting is implemented, it shall also be bounded by a programmable rate limit.
9) The block shall expose busy_out while a request is outstanding or while awaiting acceptance by the actuator interface.
10) The block shall expose fallback_out whenever the safe fallback command is active due to timeout, invalid response, software disable, or safety fault.
11) The fault latch shall be clearable only by software write to a dedicated clear_fault bit, and only when no outstanding transaction remains or after explicit abort.
12) The block shall support a software abort path that cancels pending requests, deasserts tx_valid, returns to idle, and enters safe fallback.
13) The block shall preserve request/response ordering with a single outstanding transaction unless explicitly extended by architecture; if multiple outstanding transactions are later required, add only a compact sequence scoreboard and keep the interface bounded.
14) All comparisons and counters shall be fully synthesizable using standard-cell logic.

Storage and ASIC constraints:
1) Do not infer payload memories with reg arrays, generic RAMs, or FIFO register banks for bulk data storage.
2) Small control/status registers, counters, FSM state, and one-deep descriptor latches are allowed.
3) If future architecture revisions require bulk local storage on Sky130 ASIC, use only the hard macro sky130_sram_1kbyte_1rw1r_32x256_8. Instantiate only with clk0, csb0, web0, wmask0[3:0], addr0[7:0], din0[31:0], and dout0[31:0]. Bank multiple instances only as needed.
4) Before any ASIC memory mapping using that macro, require verified behavioral Verilog, Liberty, LEF, GDS, and SPICE collateral. If collateral is incomplete or unavailable, stop at the memory-collateral gate and keep the design limited to control/status logic without bulk local storage.

Safety and control rules:
1) Reject stale model commands.
2) Clamp actuator commands.
3) Provide a safe fallback.
4) Default to safe outputs on reset and on any fault.
5) Ensure sequence/age validation occurs before command release.
6) Ensure all fault conditions are observable through status registers and fault_out.

Implementation style:
1) Use synthesizable RTL with a clear FSM for IDLE, ISSUE_REQUEST, WAIT_RESPONSE, VALIDATE_RESPONSE, APPLY_COMMAND, FALLBACK, and ABORT states.
2) Use registered outputs where practical.
3) Keep combinational paths short and suitable for ASIC synthesis.
4) Keep the design modular so the transport adapter, validator, watchdog, command limiter, and safety FSM are separable blocks.
ASIC MEMORY CONTRACT (mandatory): instantiate sky130_sram_1kbyte_1rw1r_32x256_8 for bulk payload/history/FIFO storage using clk0, csb0, web0, wmask0[3:0], addr0[7:0], din0[31:0], and dout0[31:0]. Do not expand payload, history, FIFO, or telemetry storage into individually named registers, flip-flop arrays, or inferred memories. Small control/status registers are allowed.
