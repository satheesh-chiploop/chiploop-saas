Design a UART buffered packet engine with a memory-mapped register interface.

This block is more complex than the PWM demo and should include enough state for roughly 150-200 flip-flops through FIFOs, counters, shifters, state machines, and status registers.

Top module:
- uart_packet_engine

Inputs:
- clk
- reset_n
- wr_en
- wr_addr[7:0]
- wr_data[7:0]
- rd_en
- rd_addr[7:0]
- uart_rx

Outputs:
- rd_data[7:0]
- uart_tx
- irq
- rx_fifo_level[5:0]
- tx_fifo_level[5:0]
- packet_count[15:0]

Register map:
- 0x00 CONTROL: bit 0 ENABLE, bit 1 RX_ENABLE, bit 2 TX_ENABLE, bit 3 LOOPBACK, bit 4 IRQ_ENABLE
- 0x04 BAUD_DIV: baud-rate divider[15:0]
- 0x08 PACKET_LEN: expected packet length[7:0]
- 0x0C TX_DATA: write-only TX FIFO push data[7:0]
- 0x10 RX_DATA: read-only RX FIFO pop data[7:0]
- 0x14 STATUS: tx_empty, tx_full, rx_empty, rx_full, tx_busy, rx_busy, packet_active, error
- 0x18 IRQ_STATUS: rx_done, tx_done, rx_overflow, tx_underflow, framing_error, packet_done
- 0x1C IRQ_CLEAR: write one to clear matching IRQ_STATUS bits
- 0x20 DEBUG_COUNT: packet_count[15:0], read-only

Functional requirements:
- Reset clears all registers, FIFOs, counters, shifters, state machines, status bits, and irq.
- BAUD_DIV controls a baud tick generator used by both UART RX and TX.
- UART TX serializes bytes from TX FIFO using 1 start bit, 8 data bits, no parity, and 1 stop bit.
- UART RX samples uart_rx, reconstructs 8-bit bytes, checks start/stop framing, and pushes valid bytes into RX FIFO.
- TX FIFO depth is 16 entries by 8 bits.
- RX FIFO depth is 16 entries by 8 bits.
- Firmware pushes TX bytes by writing TX_DATA when STATUS.tx_full is zero.
- Firmware reads RX bytes by reading RX_DATA when STATUS.rx_empty is zero.
- PACKET_LEN controls packet completion. RX_DONE asserts when PACKET_LEN valid bytes have been received. TX_DONE asserts when PACKET_LEN bytes have been transmitted.
- IRQ_STATUS latches completion and error events until cleared through IRQ_CLEAR.
- irq is asserted when CONTROL.IRQ_ENABLE is set and any IRQ_STATUS bit is set.
- LOOPBACK mode internally routes transmitted bytes into the RX path for firmware and verification smoke tests.
- Overflow and underflow conditions must be detected and latched.

Generate synthesizable SystemVerilog, a register map, assertions, a simulation testbench, UPF-lite collateral, and a packaging manifest.
