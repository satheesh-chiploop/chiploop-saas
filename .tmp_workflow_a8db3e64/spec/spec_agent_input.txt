The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.

FIRMWARE CONTROL-PLANE CONTRACT (mandatory): this product journey requests generated firmware. The synthesizable top must expose a real firmware-visible CSR/MMIO interface with address, write-data, read-data, transaction-valid/write-enable, and response/ready semantics. DIGITAL_SPEC_JSON.register_contract must describe the implemented registers and fields. Every declared register must be reachable through RTL decode; do not label inaccessible internal state as software-visible. The streaming transport may coexist with, but cannot replace, this interface.
The top-level module shall be named adaptive_aero_control_top and shall be synthesizable RTL intended for FPGA prototype implementation. The design shall not implement the NVIDIA DoMINO surrogate model; instead it shall implement the digital control shell around a software/GPU-executed surrogate. The top level shall use only compact interfaces: a 128-bit streaming request bus with valid/ready, a 128-bit streaming response bus with valid/ready, a 64-bit actuator command bus with valid/ready, a small 32-bit register write/read window, and scalar clock/reset/status signals. The module shall not expose geometry arrays, flow fields, tensor payloads, or other large model artifacts as top-level pins.

The request path shall accept a packed request record that includes at minimum: request sequence number, operating mode, vehicle/geometry reference selector, stream-velocity summary, optional configuration tags, and any control metadata needed by the host/software surrogate runner. The RTL shall capture the request only when s_req_valid and s_req_ready are asserted in the same cycle. The design shall provide backpressure when an outstanding request is pending, when internal buffering is full, or when a fault condition requires command suppression.

The response path shall accept a packed validated response from the host/software side. The response record shall contain at minimum: echoed sequence number, response status, freshness indication or age tag, and compact control result summary. The RTL shall compare the response sequence to the outstanding request sequence and shall reject mismatches. The RTL shall reject responses that exceed the programmable age limit or arrive after watchdog expiry. Invalid, stale, or timed-out responses shall not update actuator outputs.

The actuator command manager shall produce a compact 64-bit command word that encodes actuator target position(s), rate limit or slew intent, enable/fallback state, and optional checksum or parity. The command word shall be generated only from validated response data or from the safe fallback manager. The command_clamper shall enforce programmable lower and upper bounds on every actuator target field. Any attempted out-of-range value shall be clipped to the legal range and flagged in status.

The safe_fallback_manager shall drive a predefined safe aerodynamic configuration whenever reset is asserted, a timeout occurs, a stale response is detected, the response is invalid, or a host/software fault bit is asserted. Safe fallback shall remain active until a fresh valid response is accepted and a release condition is satisfied. Fallback shall not be disabled by software without a deliberate, documented configuration path.

The timeout_watchdog shall start when a request is accepted and shall expire after a programmable number of cycles if no valid matching response arrives. The stale_data_detector shall independently track sequence progress and/or age counters to reject delayed commands even if a response eventually arrives. Both timeout and stale-data events shall be latched in fault_status until cleared by a dedicated software write or reset.

The cfg register window shall implement small control/status registers only. Minimum registers shall include: operating mode, sequence counter, timeout limit, stale-age limit, actuator min/max bounds, fallback selector, and fault clear. The cfg interface shall never be used for bulk payload storage. If implementation requires optional request or response buffering for timing closure, the FPGA path shall use FPGA BRAM or vendor-approved FPGA memory primitives; no Sky130 hard macro shall be used in the FPGA prototype flow.

The design shall be fully synchronous to clk with active-low rst_n. All state machines shall have explicit reset values that place the controller into safe fallback. The implementation shall avoid combinational loops, shall provide one-cycle handshakes where possible, and shall register outputs on clk. Invalid configuration writes shall be ignored or flagged, not propagated into unsafe states.

The top-level scalar-equivalent I/O count shall remain below 256. The design shall be written so that it can be integrated into an automated Arch2RTL flow as a compact control-and-supervision block around a remote surrogate execution service. The RTL acceptance criterion is bounded, deterministic control behavior with stale-data detection, timeout handling, command clamping, and safe fallback, not surrogate inference accuracy.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
