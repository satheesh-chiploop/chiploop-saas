Top module: adaptive_aero_control_top.

Purpose: Implement a synthesizable FPGA control shell for intelligent active aerodynamics. The RTL shall not contain the NVIDIA DoMINO surrogate model, neural network, CFD solver, or any tensor/geometry processing beyond compact request handling and status bookkeeping.

Clocking and reset:
- Input clk and active-low rst_n.
- All sequential logic shall be synchronous to clk.
- On reset, the design shall enter SAFE_FALLBACK state, clear pending command flags, clear stale/timeout flags, and drive actuator_cmd to the configured safe position.

Processor integration:
- Instantiate PicoRV32 as the soft CPU with Wishbone-compatible memory-mapped access to control/status registers.
- The CPU firmware is responsible for preparing compact request descriptors and supervising operation.
- No top-level tensor arrays or large geometry payload buses are permitted.

Interface rules:
- The top-level external interface shall be either a bounded streaming bus of 64 bits per beat with valid/ready handshake, or a memory-mapped register window of 32-bit data width. This implementation shall use a 32-bit Wishbone slave window plus an optional 64-bit bounded host stream for compact descriptors.
- Keep total scalar-equivalent I/O below 256.
- Actuator outputs shall be narrow control signals only; no raw flow field data shall be exposed externally.

Control/status register map requirements:
- Provide registers for: mode select, safe fallback position, actuator min, actuator max, timeout threshold, stale threshold, command sequence counter, accepted sequence counter, fault status, interrupt enable, and command/response mailbox control.
- Provide readback of current accepted command, current actuator output, and fault summary.
- Provide write-one-to-clear semantics for sticky fault flags.

Command mailbox:
- Implement a bounded mailbox for compact command descriptors. Each descriptor shall include at minimum: sequence_id, timestamp or age marker, target_actuator_position, and a valid bit.
- The mailbox shall not store full geometry arrays or surrogate payloads; it may store only compact control metadata.
- A new command is accepted only if valid is asserted, the sequence_id is strictly newer than the last accepted sequence, and the age/timeout check passes.

Stale-data and timeout detection:
- Maintain a free-running age counter or deadline counter.
- If the current command age exceeds the programmed timeout threshold, assert timeout_fault, discard the command, and transition to fallback.
- If sequence_id is not newer than the last accepted sequence, assert stale_fault and reject the command.
- These faults shall be sticky until cleared by software or reset.

Actuator clamping:
- Before driving actuator_cmd, compare the requested position against actuator_min and actuator_max.
- If the request is below min, drive min and assert clamp_fault.
- If the request is above max, drive max and assert clamp_fault.
- If valid and in-range, drive the requested value and clear the clamp event for that transaction.

Fallback behavior:
- The fallback_manager shall override normal command flow whenever stale_fault, timeout_fault, transport fault, or explicit safe-mode request is active.
- In fallback, actuator_cmd shall be forced to safe_fallback_position.
- actuator_valid shall still indicate the output update when entering fallback, so downstream logic can latch the safe command.

Transport and handshake:
- The optional host stream shall use valid/ready handshake and 64-bit payload width.
- Stream payload fields shall be fixed and compact, encoded in a small packed record.
- If stream backpressure persists beyond a programmable limit, raise a transport fault and enter fallback.

Interrupt behavior:
- Raise irq_out on new accepted command, stale rejection, timeout fault, clamp event, fallback entry, and host transport fault.
- Interrupts shall be maskable via control register bits.

Firmware/software contract:
- Firmware shall periodically update watchdog and command sequence state.
- Firmware shall read fault status and clear sticky flags only after safe recovery.
- The control algorithm may reside in firmware or external software; RTL only guarantees bounded transport and safety enforcement.

Implementation constraints:
- FPGA-only path: use FPGA BRAM abstractions only if buffering is required; do not instantiate Sky130 macros.
- Do not infer large payload memories as flip-flop arrays for model data.
- The design may use small registers and small FIFOs for control traffic only.
- Ensure synthesizable RTL with enumerated state machine for SAFE_FALLBACK, IDLE, ACCEPT, CLAMP, and ERROR states.

Outputs:
- actuator_cmd[15:0]
- actuator_valid
- fault_out[3:0]
- irq_out

Acceptance criteria:
- Commands older than the configured stale threshold are rejected.
- Commands beyond timeout are rejected.
- Actuator outputs are always clamped to the programmed range.
- Safe fallback is asserted whenever faults are present or transport is unavailable.
