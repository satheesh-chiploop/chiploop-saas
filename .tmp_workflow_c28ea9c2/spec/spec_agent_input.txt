Design an automotive safety fault manager and watchdog controller with a memory-mapped register interface.

Top module:
- safety_fault_watchdog

Inputs:
- clk
- reset_n
- wr_en
- wr_addr[11:0]
- wr_data[31:0]
- rd_en
- rd_addr[11:0]
- heartbeat
- fault_in[7:0]
- external_reset_done

Outputs:
- rd_data[31:0]
- safety_irq
- reset_request
- fault_latched[7:0]
- escalation_level[1:0]
- watchdog_expired

Register map:
- 0x000 CONTROL: bit 0 ENABLE, bit 1 WATCHDOG_ENABLE, bit 2 IRQ_ENABLE, bit 3 FAULT_CLEAR
- 0x004 STATUS: healthy, watchdog_expired, fault_pending, reset_requested, escalation_active
- 0x008 WATCHDOG_TIMEOUT: timeout value in controller ticks[31:0]
- 0x00C HEARTBEAT_COUNT: observed heartbeat count[31:0]
- 0x010 FAULT_MASK: enabled fault inputs[7:0]
- 0x014 FAULT_STATUS: latched fault inputs[7:0]
- 0x018 ESCALATION_POLICY: warn threshold, reset threshold, shutdown threshold fields
- 0x01C ESCALATION_LEVEL: 0 none, 1 warning, 2 reset, 3 shutdown
- 0x020 IRQ_STATUS: watchdog, fault, reset_request, escalation
- 0x024 IRQ_CLEAR: write one to clear IRQ_STATUS bits
- 0x028 RESET_COUNT: reset request count[31:0]

Functional requirements:
- Reset clears counters, status, latched faults, IRQ, reset_request, and escalation state.
- WATCHDOG_ENABLE starts a down counter that is refreshed by heartbeat.
- If heartbeat is not observed before WATCHDOG_TIMEOUT, watchdog_expired latches and IRQ_STATUS.watchdog asserts.
- Enabled fault_in bits latch into FAULT_STATUS and fault_latched.
- Escalation level increases based on repeated watchdog/fault events using ESCALATION_POLICY.
- reset_request asserts when escalation reaches reset level and clears after external_reset_done.
- FAULT_CLEAR and IRQ_CLEAR clear corresponding latched state without clearing RESET_COUNT.
- safety_irq asserts when IRQ_ENABLE is set and any IRQ_STATUS bit is set.

Generate synthesizable SystemVerilog, a register map, assertions, a simulation testbench, UPF-lite collateral, and a packaging manifest.
