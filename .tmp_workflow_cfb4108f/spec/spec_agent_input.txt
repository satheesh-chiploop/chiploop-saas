The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.

FIRMWARE CONTROL-PLANE CONTRACT (mandatory): this product journey requests generated firmware. The synthesizable top must expose a real firmware-visible CSR/MMIO interface with address, write-data, read-data, transaction-valid/write-enable, and response/ready semantics. DIGITAL_SPEC_JSON.register_contract must describe the implemented registers and fields. Every declared register must be reachable through RTL decode; do not label inaccessible internal state as software-visible. The streaming transport may coexist with, but cannot replace, this interface.
Design a synthesizable FPGA RTL top module named adaptive_aero_control_top. The module shall not implement the NVIDIA DoMINO surrogate itself; it shall provide hardware support for request/response transport, validation, buffering, safety, and actuator command handling for an intelligent active-aerodynamics controller.

1. Top-level interface
- Use a compact implementation-friendly interface.
- Supported top-level ports shall be limited to clock/reset, a 64-bit register-mapped control window or equivalent narrow streaming control input, a 64-bit status window or equivalent narrow streaming status output, one 128-bit valid/ready request stream to an external CPU/GPU surrogate service, one 128-bit valid/ready response stream from that service, and a 32-bit actuator command output stream.
- Do not expose tensors, geometry arrays, pressure fields, or flow fields as top-level pins.
- Keep scalar-equivalent I/O below 256.

2. Functional partition
- cfg_regs: programmable registers for operating mode, velocity setpoint, timeout threshold, sequence ID seed, command clamp bounds, fallback mode selection, and fault clear.
- cmd_parser: accepts configuration writes and command trigger events; packages a compact request descriptor for the external surrogate service.
- request_buffer: stores at least one outstanding request descriptor and its metadata. For FPGA, implement using platform BRAM or distributed RAM as appropriate.
- response_buffer: stores at least one response descriptor and metadata.
- staleness_guard: checks sequence number match, response validity, and response age against timeout threshold.
- safety_manager: enforces command clamping, illegal-state detection, fault latching, and safe-state entry.
- actuator_mapper: maps validated aerodynamic intent to a 32-bit actuator command word.
- fallback_controller: provides deterministic safe actuator command values for low-drag/neutral safety mode as configured.
- status_telemetry: publishes mode, busy, valid, timeout, stale, fault, and last-accepted sequence information.

3. Request/response protocol
- The request stream shall transmit a packed descriptor containing: request_valid, request_sequence_id, current operating mode, configured stream velocity, vehicle-state summary fields, and a compact job tag.
- The response stream shall transmit a packed descriptor containing: response_valid, response_sequence_id, result-valid flag, result age or timestamp tag, compact drag/lift summary fields, and health/status flags from the external service.
- The RTL shall not assume surrogate inference runs on-chip. The external compute path may be CPU reference, NVIDIA-hosted NIM, or GPU worker; the RTL remains agnostic.
- Only a compact summary of surrogate outputs shall be consumed on-chip; full flow fields and pressure maps remain off-chip.

4. Safety and control behavior
- On reset, the module shall enter safe fallback mode and output a safe actuator command.
- When a command trigger is received, the module shall issue a request only if not already waiting for an outstanding request or if overwrite is explicitly enabled by configuration.
- If no matching response arrives before timeout expiration, the module shall discard the transaction, assert timeout status, and drive fallback actuator output.
- If a response arrives with mismatched sequence ID, invalid flag, or stale age, the module shall reject it and keep or enter fallback mode.
- Before actuator output update, the command shall be clamped to configured minimum and maximum limits.
- If any fault is latched, the module shall continue safe fallback output until fault-clear is requested and the system is revalidated.

5. State machines
- Implement deterministic FSMs for idle, request_issued, waiting_response, validate_response, command_update, fallback, and fault_latched states.
- State transitions shall be fully synchronous and reset-safe.
- No combinational loops are permitted in ready/valid control paths.

6. Storage and buffering
- For FPGA implementation, use BRAM or equivalent FPGA memory resources for request/response buffering.
- Do not infer ASIC bulk payload memory as register arrays.
- No Sky130 hard macro shall be instantiated in the FPGA prototype.
- If the project is later retargeted to Sky130 ASIC, bulk payload storage shall only use sky130_sram_1kbyte_1rw1r_32x256_8 with the required ports clk0, csb0, web0, wmask0[3:0], addr0[7:0], din0[31:0], and dout0[31:0], and only after confirming availability of behavioral Verilog, Liberty, LEF, GDS, and SPICE collateral.

7. Timing and throughput
- The design shall support bounded latency control flow suitable for periodic vehicle-control updates.
- Handshake logic shall respect valid/ready semantics and shall not drop a transaction without status reporting.
- The module shall remain functional when the external surrogate service is unavailable by entering fallback mode.

8. Observability
- Expose status bits for busy, request_outstanding, response_seen, stale_response, timeout_error, invalid_response, fallback_active, fault_latched, and last_sequence_id.
- Expose counters for request_count, accepted_response_count, rejected_response_count, and timeout_count, using compact registers only.

9. Non-goals
- Do not implement the DoMINO model, geometry meshing, CFD, flow-field reconstruction, or GPU scheduling in RTL.
- Do not infer broad payload memories with flip-flops.
- Do not rely on unbounded FIFOs or unbounded top-level buses.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
