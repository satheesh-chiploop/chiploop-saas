Module name: adaptive_aero_control_top.

Purpose: Synthesizable FPGA digital IP for intelligent active-aerodynamics supervision. The RTL shall implement request/response transport, freshness checking, timeout detection, command validation, actuator clamping, and safe fallback. The physics surrogate itself is external and not part of RTL.

Top-level ports shall be limited to a bounded interface. Use a 128-bit streaming request port, a 128-bit streaming response port, a 64-bit CSR window, a small actuator command output, clock, reset, and fault inputs. Do not expose geometry arrays, tensor payloads, or flow fields as individual pins.

Functional requirements:
1. Reset behavior: On reset assertion, all state machines shall enter SAFE mode, actuator outputs shall drive a default conservative position, error flags shall clear to known state, and no command shall be issued until a valid request/response transaction completes.
2. Request handling: The design shall accept a host command packet on host_cmd_if only when cmd_valid and cmd_ready are asserted. The packet shall include, at minimum, a packet type field, transaction ID, freshness or sequence field, flow-condition metadata, and control mode bits. Invalid packet type or malformed header shall be rejected.
3. Response handling: The design shall accept a response packet on host_rsp_if only when rsp_valid and rsp_ready are asserted. The response shall be checked against the outstanding transaction ID and freshness constraints. Mismatched or late responses shall be dropped and flagged.
4. Stale-data detection: Maintain a request age counter and a watchdog timer. If the age exceeds a programmable threshold, assert stale_data and force safe fallback. Late responses shall not update actuator commands.
5. Timeout handling: If no valid response is observed before timeout expiration, assert timeout_fault, transition to SAFE mode, and hold the fallback command until cleared and revalidated.
6. Command validation: Validate all received actuator-intent fields against programmable min/max limits, slew-rate limits, and allowed mode encodings. Any out-of-range or illegal command shall be clamped or rejected according to a programmable policy, with rejection preferred when safety is ambiguous.
7. Safe fallback: The design shall support at least one safe fallback policy selectable by CSR: hold-last-safe, preloaded safe table entry, or fixed conservative position. Safe fallback shall be used whenever stale_data, timeout_fault, cmd_invalid, sensor_fault, host_timeout, or overrange are present.
8. Actuator mapper: Translate validated control intent into a compact actuator command code and position field. Output shall be registered and synchronized to act_cmd_ready. Actuator outputs shall never exceed configured clamp bounds.
9. CSR window: Implement a 64-bit register window for configuration and status. Required registers include control mode, timeout threshold, freshness threshold, clamp min/max, safe fallback selector, sequence counters, sticky fault flags, and version ID.
10. Sequencing: Maintain a monotonically increasing accepted-sequence counter. Accept only one outstanding request at a time unless a CSR enables a small bounded pipeline depth of 2. Default pipeline depth shall be 1.
11. Fault latching: timeout, stale, invalid_packet, and clamp_violation shall be sticky until cleared through CSR write-one-to-clear semantics. Clearing shall not exit SAFE mode unless the next transaction is valid.
12. Clocking and timing: All logic shall be synchronous to the single FPGA system clock. No asynchronous combinational feedback shall be used in control decisions.
13. Resource policy: The design may use FPGA BRAM or distributed RAM for small FIFOs or fallback tables, but shall not infer ASIC SRAM macros, and shall not instantiate any Sky130 memory macro in the FPGA path.
14. Software contract: Host software shall provide geometry token/reference ID and flow conditions. The RTL shall not parse STL or geometry meshes; it only transports metadata and validates sequence/freshness.
15. Observability: Status outputs shall expose current mode, outstanding transaction ID, age counter, timeout status, stale status, invalid status, fallback active, and actuator clamp-active indication.

Packet format guidance for 128-bit streaming words:
- Bits 7:0 packet_type
- Bits 23:8 transaction_id
- Bits 31:24 version or reserved
- Bits 47:32 flow_velocity_mps scaled field or integer encoding
- Bits 63:48 control request field or mode field
- Bits 95:64 geometry reference token / host handle
- Bits 111:96 freshness counter / timestamp low bits
- Bits 127:112 flags, checksum, or reserved
Implement exact field mapping in RTL documentation and lock it for software integration.

Register window guidance for 64-bit CSR accesses:
- address 0x00 control/mode
- address 0x08 timeout and freshness thresholds
- address 0x10 clamp min/max
- address 0x18 status and sticky fault clear
- address 0x20 sequence counters
- address 0x28 version and capability ID

Safety-critical outputs shall default to safe values if any CSR access is invalid or if host-side sequencing is broken. The design shall be fully synthesizable and use only standard FPGA digital primitives plus optional BRAM inference for bounded internal storage.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
NO COMMAND FALLBACK CONTRACT (mandatory; overrides conflicting generated prose): do not create a fallback command, fallback register, fallback status, fallback controller, substitute command, or fallback-on-reset behavior. On invalid, stale, timeout, reset, or fault conditions, inhibit/deassert actuator output validity and latch the fault for software handling. Do not silently replace the requested command.
