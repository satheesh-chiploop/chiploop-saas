The required synthesizable top module is adaptive_aero_control_top. Do not substitute a status, telemetry, register-bank, or leaf module as the design top. The top must implement the selected Physical AI application contract, external model request/response transport, validation, safety, timeout, fallback, and bounded actuator-command behavior.

EXTERNAL MODEL TRANSPORT DIRECTION CONTRACT (mandatory; this takes precedence over ambiguous ingress/egress wording in upstream prose): the RTL emits model-request valid/data as outputs and receives model-request ready as an input. The RTL receives model-response valid/data as inputs and emits model-response ready as an output. Apply this rule by data flow even when application-specific ports use cmd_*, req_*, rsp_*, or response_* names. A top-level output must have a real RTL driver; never connect a required top-level output only to a child input.
Design a synthesizable FPGA digital IP named adaptive_aero_control_top for an intelligent active-aerodynamics controller. The RTL implements transport, validation, safety, and actuator command handling only; it does not implement the NVIDIA DoMINO surrogate itself. The top-level interface shall be compact and implementation-friendly, using either a small register-memory window or a bounded valid/ready streaming bus. For this project, implement both a 32-bit register window and 64-bit bounded request/response streams, with no top-level port wider than 64 bits and no exposed geometry arrays, tensors, or flow fields.

Functional requirements:
1. Configuration/control plane:
   - Implement an 8-bit addressable, 32-bit register file for mode control, timeout programming, command limits, fallback command, transaction counters, and status readback.
   - Include registers for: enable, clear_faults, operating_mode, stream_velocity_setpoint, timeout_cycles, stale_age_limit, actuator_min, actuator_max, fallback_command, last_txn_id, last_rxn_id, and sticky fault bits.
   - Register writes shall be accepted only when cfg_valid and cfg_ready are asserted. Reads shall return the addressed register on cfg_read.

2. Request transport:
   - Accept 64-bit req_data with req_valid/req_ready handshaking.
   - req_data shall contain compact metadata only, such as transaction ID, stream velocity, geometry reference tag, and control flags. It shall not contain full geometry payloads or surrogate tensors.
   - On acceptance of a request, capture the transaction ID and issue a request-pending state for the response watchdog.
   - The formatter may optionally emit a request descriptor into a small internal FIFO or BRAM buffer, but only if required for timing closure; for FPGA, use vendor BRAM primitives or inferred block RAM, not register arrays for bulk storage.

3. Response transport:
   - Accept 64-bit response payloads through a local response parser stage that can be connected to a software/GPU bridge or host DMA interface in the larger system.
   - Response data shall include at minimum transaction ID, validity flags, command recommendation, and status bits. Since the surrogate executes externally, RTL only validates and consumes these fields.
   - Response is valid only when transaction ID matches the outstanding request, freshness age is within limit, and no parser error is present.

4. Safety monitor:
   - Implement a watchdog that starts on request acceptance and expires after timeout_cycles.
   - Implement stale-data detection based on response age or a response timestamp/age field when present; stale responses must be rejected.
   - Implement a parser-error detector for malformed response framing, ID mismatch, unsupported mode, out-of-range fields, or invalid status combinations.
   - Any watchdog expiry, stale response, parser error, or explicit fault input shall assert fault_status and force safe fallback.

5. Actuator command handling:
   - Compute an internal candidate command from the validated response. The RTL may pass through a command recommendation field from the response or select a fallback command if the response is invalid.
   - Clamp the final actuator command to [actuator_min, actuator_max] before driving act_cmd.
   - Optionally rate-limit transitions using a programmable delta limit if included in the register set.
   - act_enable shall deassert in fallback or fault modes unless configured to hold last-safe command.

6. Safe fallback:
   - Define a deterministic safe fallback state that outputs fallback_command and asserts act_fault.
   - Safe fallback must be entered on reset, timeout, stale data, malformed response, or invalid configuration.
   - Sticky faults shall remain asserted until clear_faults is written and the fault condition is absent.

7. Telemetry:
   - Provide status outputs for fault bits, last transaction ID, response age, clamp-active, fallback-active, request-pending, and watchdog-expired.
   - Provide cfg_rdata readback for diagnostic use.

8. Timing and synthesis:
   - The design must be fully synthesizable for FPGA.
   - Use synchronous design practices with a single clk domain unless a clearly bounded CDC wrapper is added externally.
   - Do not infer ASIC hard macros or Sky130 SRAM macros in this FPGA path. If later retargeted to ASIC, memory collateral must be explicitly qualified before using any hard macro. For this FPGA prototype, platform BRAM is the only acceptable bulk storage style.

9. Non-functional constraints:
   - Keep top-level scalar-equivalent pin count below 256.
   - Keep all top-level bus widths at 64 bits or less.
   - Preserve deterministic behavior under reset, invalid input, and missing response conditions.
   - The design shall not claim surrogate accuracy; it only manages request/response transport and safety envelope enforcement.

10. Integration note:
   - The external software/GPU service performs DoMINO inference using the supplied vehicle_geometry and flow_conditions. RTL may only move compact descriptors and results between host logic and actuator control. Do not hardwire model internals into RTL.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
