Module name: adaptive_aero_control_top.

Purpose: Synthesizable FPGA digital-IP wrapper for intelligent active aerodynamics control. The RTL shall not implement the NVIDIA DoMINO model. Instead, it shall provide bounded request/response transport, register access, safety supervision, stale-command rejection, timeout handling, actuator clamping, and fallback control.

Top-level ports shall be implementation-friendly and compact. Use a Wishbone control/status interface for the PicoRV32 subsystem and a bounded streaming interface for model request/response traffic. Do not expose vehicle geometry, mesh, tensor, pressure map, or flow-field arrays at top level.

Clock/reset:
- Single primary clock domain at the FPGA system clock specified by integration.
- Synchronous active-high or active-low reset may be selected by integration, but reset behavior must drive the actuator output subsystem to safe fallback until firmware releases enable.

Wishbone register window:
- Implement a 64-bit-or-narrower register access policy per transaction; internal register file may be 32-bit aligned.
- Mandatory registers include: control, status, timeout_threshold, stale_sequence_limit, actuator_min, actuator_max, safe_fallback_value, current_sequence, last_valid_sequence, last_valid_age, fault_latch, and enable.
- Optional registers include telemetry counters and mode select.
- A write to control.enable shall arm closed-loop operation only if no fault latch is set and configuration is valid.
- A write to fault-clear shall clear latched faults only when the safety supervisor reports idle or safe state and firmware acknowledges the event.

Request path:
- Input from firmware/control logic into the request_packager shall be encoded in a bounded 128-bit stream word or smaller.
- req_valid shall assert only when a complete request word is available.
- req_ready shall gate acceptance of the word.
- Request metadata shall include a monotonically increasing sequence number, a timestamp or age tag, a speed bin or speed value, current actuator context, and command mode flags.
- If the downstream model gateway is not ready, the request packager shall hold the request stable without corrupting state.

Response path:
- rsp_valid/rsp_ready shall use the same bounded streaming discipline.
- The response_checker shall validate the sequence number, freshness against timeout_threshold, and basic format correctness.
- Responses failing validation shall be rejected and shall not update actuator commands.
- On accepted response, the valid command word shall be forwarded to the actuator_output_manager.

Stale-data detection:
- Maintain an internal age counter or timer per outstanding request.
- Compare received response age to programmable timeout_threshold.
- Any response older than threshold or with a sequence number not matching the outstanding request shall set a stale fault and inhibit actuator update.

Timeout handling:
- If the outstanding request expires before a valid response is accepted, the safety_supervisor shall assert timeout fault, latch it, and command fallback value.
- Timeout operation shall not depend on external software intervention to enter safe state.

Actuator command handling:
- Output a compact actuator command word no wider than 64 bits.
- Clamp all actuator positions/deflections to programmable min/max bounds before driving act_valid.
- If control.enable is deasserted or a fault latch is set, output safe_fallback_value and/or inhibit act_valid according to integration policy.
- The module shall support at least one active-aero actuator group; firmware may encode multiple surfaces into the compact command word.

Safety supervisor:
- Implement combinational and sequential checks for invalid configuration, malformed payload, stale response, timeout, and watchdog events.
- Provide sticky fault bits and IRQ outputs for fault, update, and timeout events.
- Provide a clear path for firmware to acknowledge and recover from safe fallback after fault correction.

Storage implementation policy:
- For FPGA prototype, use the platform BRAM abstraction for any nontrivial buffering if required by integration.
- Do not expose or infer bulk payload storage as large flip-flop arrays.
- Small control registers, counters, and FSM state are allowed.
- Do not instantiate any Sky130 macro in the FPGA path.

Timing and throughput:
- The interface shall support bounded, deterministic request/response operation suitable for 50 MHz soft-CPU supervision.
- Backpressure must be honored on all valid/ready channels.
- No unbounded queues are permitted in RTL.

Firmware/software interaction:
- Firmware shall write configuration registers, launch requests, poll or interrupt on response availability, and read back status/fault flags.
- The RTL shall remain deterministic and shall never infer the aerodynamic prediction itself.

Reset and startup:
- After reset, outputs must be in safe state, faults cleared or held according to integration policy, and enable must default to disabled.
- The design shall not assert actuator commands until configuration is valid and enable is set.

Implementation acceptance criteria:
- Synthesizable Verilog/SystemVerilog RTL.
- No top-level tensor arrays or geometry ports.
- Compact top-level pin count under 256 scalar-equivalent I/Os.
- Wishbone-compliant CPU access and bounded streaming data paths.
- Explicit stale-data rejection, timeout handling, clamping, and safe fallback.
FPGA MEMORY CONTRACT (mandatory): describe bulk payload/history/FIFO storage through a technology-neutral memory wrapper that the FPGA flow can map to native block RAM; do not flatten it into registers.
